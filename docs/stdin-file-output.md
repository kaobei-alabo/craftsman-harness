# Private stdin to guarded one-file publication

**Status: October 25, 2026 (Asia/Taipei).** This incomplete implementation adds a separate
`StdinFileInvocation`; it does not expose `craftsman exec`, flags, stdout/stderr,
public outcomes/results/events, usage, storage/trace or headless gadget callables.

Exact positional `-` and all attachment/destination grammar precede IO. The SAME
Bootstrap/captured credentials/ConfinedFs supplies native input and retained source
roots. Read-only output capture happens BEFORE even inspecting stdin. Whole native
EOF/UTF-8/BOM/attachment/frame admission and restored/closed input precede a SECOND
retained target/absence check, then session IDs/store and the SAME runtime builder.
Only this opaque pre-run preparation constructs the existing file invocation;
returned FileRun/FileTerminal/Record and guarded publication remain unchanged.

No caller Run/target/data/gates/seeds pairing, new generic reader/publisher, output
path/format switch, input grant or IO fallback is introduced. Old argument/file,
plain native-stdin and file-output entry points keep their bodies/behavior. Bounds
and native limitations remain those of [named-stdin.md](named-stdin.md) and
[guarded-output.md](guarded-output.md). Invalid destinations refuse before input
consumption; a later target change can refuse after consumed input, without rewind
or a raw spill/retry. Before-session rechecks are NOT an external-writer/namespace
CAS or OS/cancellation/global-stdin/durability guarantee. Public enablement and
R2/#97/P2g remain independent/open. Every partial slice includes docs and requires
ALL FOUR fresh exact-final-head jobs/every mandatory step, Windows included,
before any missing-review-only admin merge.
