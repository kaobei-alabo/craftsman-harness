# Private normal-session capture and prospective CRUD

The app implements a private, selected TUI/ACP read-capture owner and pure CRUD
preview foundation. Every public route leaves the opaque selection absent.
Only marked native tests select it inside actual frontend construction. Existing
model tools, gadget calls, configuration fields, CLI commands and ACP frames
do not route through it. Interpreter backend selection remains a later slice.

The shared normal builder resolves its actual working folder and configuration
origin, retains native directory authority, and pairs the owner with its actual
approval policy, backend and committed Agent identity. Legacy, service, frozen
and private prepared construction reject a supplied frontend selection before
effects. ACP retains its existing non-durable checkpoint policy; capture does
not set cancellation_session.
The identity is a pure framework per-built-Agent witness, minted only by
AgentBuilder. Clones and moves retain it; fresh builders sharing state,
backend, registry, names or the original tool handle receive a different
witness. Capture checks that witness against the actual Agent and its immutable
backend, in addition to the original selected context, state, tool, root,
policy and generation. The identity supplies no read or task permission.

Only explicitly selected relative file names under that one session folder
are inspected. There is no recursive inventory, Git requirement, home scan,
common-parent root inference or read popup. Additional human task roots are
not implemented. The first subset requires an existing supported actual config
directory. Config/credential/runtime names and identities are denied, including
the actual configuration origin and current executable.

Native reads reuse the confined reader's basename grammar, no-follow directory
operations and platform read-only/nonblocking open options. They retain parent
identities, support regular single-link files only, and capture exact whole
binary bytes plus EOF and native path/handle evidence. Empty existing files are
present. Only an exact missing leaf under a retained existing parent is absent.
Missing parents, unsupported files, denial and incomplete/raced reads refuse the
whole set. A missing record never supplies CREATE or DELETE authority.

Bounds are 128 targets, 64 KiB per file, 192 KiB original bytes, 32 KiB selected
path bytes, 16 relative components, 128 absolute directory components, 16,384
counted native facade operation attempts per batch and 128 read/EOF attempts per file. Whole target/size/type
admission precedes content copying. Native handles have no writer, deletion,
directory-access or Deref interface.

Each immutable snapshot binds its unique session owner, retained root/config
identities, actual generation and capture serial. Thread/load/transfer/rebuild
operations invalidate old generations; rebuild/transfer/close and owner drop seal admission.
Explicit frontend close awaits retained read workers, including when a caller
drops its capture wait. Already-started blocking native calls cannot be forcibly
interrupted by future drop. Initialization reads retain their inputs/handles
through actual return but cannot publish an unbound owner. Existing frontend
shutdown bounds and blocking-worker limitations remain; there is no OS
quiescence, portable filesystem latency or containment claim.
Historical objects retain private read/directory handles until those objects
are dropped; closing eligibility does not claim every native handle is closed.

Native completion is separate from successful capture acceptance. Each capture
observes its actual current turn before admission, during native work, around
supervisor publication, after the receiver wakes, through publisher settlement
and immediately before a successful return. A stopped capturing turn receives
Revoked in the post-native/pre-publication and queued-receiver/wake windows.
This adds no native reread, replay, rollback, model call or VM cancellation.
One latest complete native evidence frame of at most 1 MiB may remain privately
owned after refused or abandoned delivery. It is bounded historical data,
has no context/permit/native handles, and is never treated as successful
delivery or persisted as a new checkpoint/flag.

An already accepted snapshot or preview remains historical information when
only its former turn is stopped, while its actual session/read policy/generation
remain valid. Historical readout does not mint task, source, execution, review
or apply authority. Starting another capture or deriving a new preview in a
currently stopped turn fails before work; a real stop during preview derivation
also refuses the new return. Session close/rebuild/transfer and generation
changes still invalidate old objects as the original cases require.

The preview accepts strict complete final-candidate data for captured targets
only. It derives absent-to-file CREATE, changed-file UPDATE and file-to-absent
DELETE, including empty and binary files. Restoration and transient
create/delete are no-ops; omission never deletes. Duplicate/aliased names,
unknown targets, supplied before hashes/source/permission labels, extra or
unsupported metadata, malformed base64 and whole-plan overflow refuse the plan.
Candidate bytes share the 128/64 KiB/192 KiB bounds. Complete encoded review,
including exact original/candidate bytes, operations, metadata and bindings,
must fit 1 MiB; no required content is clipped.

Windows keeps native creation time separate from by-handle ChangeTime, preserves
full native timestamp fields, and uses full 128-bit file identifiers. Metadata
is checked within each source before/after pair and across fields with the same
meaning. Access times are retained exactly but may change from the read itself.
Unsupported native information refuses capture. Windows namespace/ACL behavior
remains best effort; a held directory can prevent a rename. PR #31's independent
main proof below includes the actual Windows core and gadget modes and their
unchanged full-field child assertions; it does not establish OS containment.

A preview is labeled **historical-prospective**. It does not re-read current
content or establish staleness, approval, source consent, native permission or
an apply receipt. There is no apply, rollback, external-writer CAS, multi-file
transaction, exactly-once or undo interface. Source/image consent, accepted-human
task identity/root derivation, dedicated VM hosting, package admission,
execution cancellation, catalog/authoring/delegation/public routes and
review/scoped-auto/native apply remain later slices.

Marked tests use actual TUI/ACP builders, original config bytes, synthetic
loopback HTTP, real files and SQLite, with immutable child environments.
They cover default absence, foreign/private rejection, raw/empty/absent inputs,
hard denies and aliases, link/device/parent refusals, bounded non-Git selection,
real races, generation/rebuild/close revocation, malicious/empty/binary CRUD,
whole bounds and dropped-wait join ownership. Unmarked/unknown/duplicate helper
markers return before config/environment/artifact work. Targeted local commands,
source hashes, inventories and all failed attempts are retained under
target/verification/session-script-capture/; they do not replace the full
local17, four exact-head hosted jobs/every mandatory step/both native modes,
warning/tree and independent-main gates for each later implementation slice.
